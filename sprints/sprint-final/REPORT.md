## ขอบเขตงาน
### 1. AI Companion (คำสั่ง `talk`)
- ผู้ใช้พิมพ์ข้อความคุยกับสัตว์เลี้ยง AI ตอบในบทบาทของสัตว์เลี้ยงตัวนั้น
- ส่งสถานะปัจจุบันเป็น context: ชื่อ, ความหิว, พลังงาน, ความสุข, อารมณ์
  เช่น แมวหิว 85 → AI ขออาหาร · แมวมีความสุข → AI ชวนเล่น
- การคุยเพิ่มความสุขเล็กน้อย (AI เป็นส่วนหนึ่งของ Business Logic ไม่ใช่ chatbot แยก)
- บันทึกทั้งข้อความผู้ใช้และคำตอบลงประวัติ (`kind = talk`) ค้นหา/กรองได้เหมือนรายการอื่น
- เก็บ API key ใน environment variable ห้าม commit ลง repo
- ไม่มี key / API timeout / API ตอบผิดรูปแบบ → ตอบข้อความสำรองตามอารมณ์ โปรแกรมไม่พัง

### แผนสถาปัตยกรรม
```text
ผู้ใช้ (CLI talk / กล่องสนทนาบนเว็บ)
        ↓
PetService.talk()      ← เพิ่มเมธอดเดียว CLI และเว็บได้ใช้พร้อมกัน
        ↓
PetCompanion.reply(pet, message)     src/companion.py (ใหม่)
   ├─ มี API key → เรียก AI API พร้อม system prompt ที่มีสถานะสัตว์เลี้ยง
   └─ ไม่มี / ล่ม → คำตอบสำรองตามอารมณ์
        ↓
บันทึกสถานะ + Interaction History
```

### 2. CI/CD
- รัน flake8 แบบเต็ม (ปัจจุบันตรวจเฉพาะ error ร้ายแรง)
- รัน pytest บน Python 3.10 และ 3.12 (matrix)
- อัปเดต actions เป็นเวอร์ชันล่าสุด

### 3. Automated Testing
- เทสต์ `PetCompanion`: ไม่มี key, API สำเร็จ (mock), API ล่ม, ข้อความว่าง/ยาวเกิน
- เทสต์ `talk` ผ่าน Service และ Web API
- ยืนยันว่าเทสต์ทั้งหมดรันได้โดยไม่ต้องใช้อินเทอร์เน็ต

## Definition of Done
- [ ] `talk` ใช้ได้ทั้ง CLI และเว็บ และคำตอบเปลี่ยนตามสถานะของสัตว์เลี้ยง
- [ ] ไม่มี API key หรือ API ล่ม → ตอบแบบออฟไลน์ ไม่ crash
- [ ] ประวัติกรอง `talk` แล้วเห็นทั้งข้อความผู้ใช้และคำตอบ
- [ ] GitHub Actions ผ่านทั้ง flake8 และ pytest บน 2 เวอร์ชัน Python
- [ ] ไม่มี API key อยู่ใน repo
